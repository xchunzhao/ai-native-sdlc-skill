# Contributing

Changes to AI-Native SDLC affect both a portable Skill package and the repository that maintains it. Preserve that boundary, validate deterministic behavior first, and run model-backed regression for semantic changes.

## Repository boundaries

The installable unit is:

```text
skills/ai-native-sdlc/
```

Only files required while using the Skill belong there:

- `SKILL.md` and the bundled `LICENSE`
- templates under `assets/`
- stage and governance guidance under `references/`
- machine-readable contracts under `schemas/`
- runtime bootstrap and validation commands under `scripts/`

Repository-only material stays outside the package:

- `tests/` and fixtures
- `evals/` and frozen baselines
- maintainer scripts under root `scripts/`
- CI configuration and contributor documentation

Do not add `tests/`, `evals/`, regression code, local hooks, telemetry, credentials, account identifiers, or workstation paths to the installable package. `scripts/validate_package.py` enforces the boundary.

## Local requirements

- Python 3.10 or newer
- Git
- An authenticated GitHub Copilot CLI or Claude CLI only when running model-backed semantic regression

The deterministic test and runtime code use the Python standard library; no project dependency installation is required.

## Make a change

1. Read `skills/ai-native-sdlc/SKILL.md` and the reference governing the behavior being changed.
2. Keep the main Skill concise. Put detailed rules in a focused reference and point to it from `SKILL.md`.
3. Keep templates, schemas, prose rules, runtime validation, and tests consistent. A rule expressed in only one layer is likely to drift.
4. Add or update a deterministic test for machine-enforced behavior.
5. Add or update an evaluation case when model behavior or artifact quality changes.
6. Run the checks required for the change class below.

## Required checks

Run these for every change:

```bash
python3 -m unittest discover -s tests -v
python3 scripts/validate_package.py
python3 scripts/regression.py --check
```

The package validator confirms that the Skill is self-contained, its runtime launchers are executable, required resources exist, relative links resolve, and maintainer-only files have not leaked into the installable directory.

### Validation by change type

| Change | Deterministic tests | Package validation | Baseline integrity | Full semantic regression |
|---|---:|---:|---:|---:|
| README or contributor prose only | Required | Required | Required | No |
| Runtime script or schema | Required | Required | Required | When model-facing behavior changes |
| `SKILL.md`, template, stage guide, lifecycle, approval policy | Required | Required | Required | Required |
| Evaluation runner or rubric | Required | Required | Required | Required before merge |
| Frozen baseline | Required | Required | Required | Required twice with the same pinned model |

## Semantic regression

Run the complete suite after changing model-facing instructions:

```bash
python3 scripts/regression.py
```

Useful variants:

```bash
python3 scripts/regression.py --case feature-intent
python3 scripts/regression.py --backend copilot
python3 scripts/regression.py --backend claude
python3 scripts/regression.py --model <supported-model>
python3 scripts/regression.py --json
```

Exit codes:

- `0` — every case is stable or improved
- `1` — at least one regression
- `2` — runner, suite, baseline, or model-backend failure

Reports are written under `~/.cache/ai-native-sdlc-regression/` unless `--workspace` overrides the location. See [`evals/REGRESSION.md`](evals/REGRESSION.md) for the evaluation contract.

## Baseline changes

Do not promote a baseline from a single favorable judge run.

1. Pin the same model for comparable runs.
2. Run the complete suite twice.
3. Confirm every case is stable or improved in both runs.
4. Inspect generated artifacts and deterministic structural results.
5. Replace only reviewed baseline artifacts.
6. Keep baseline changes separate from unrelated protocol changes so reviewers can see evaluation-policy movement.

## Runtime command changes

Runtime commands must remain inside `skills/ai-native-sdlc/scripts/` and work after that directory is copied independently of the repository. Keep the extensionless POSIX launcher and Python implementation aligned:

```text
bootstrap  → bootstrap.py
sdlc-check → check.py
```

Do not make runtime commands depend on repository-root tests, evals, maintainer scripts, hidden local files, or network access.

## Privacy and local files

Never commit:

- `.github/hooks/` generated by an agent host
- absolute home-directory or workstation paths
- email addresses or account IDs used only for local configuration
- tokens, credentials, session data, or private endpoint configuration

Local hook directories are ignored by `.gitignore`, but contributors must still inspect new configuration before publishing it.

## Pull-request checklist

- [ ] The change belongs on the runtime-package or repository-maintainer side of the boundary.
- [ ] Public behavior and install instructions are reflected in `README.md` when applicable.
- [ ] `SKILL.md` links every new model-facing resource it expects an agent to read.
- [ ] Templates, schemas, lifecycle prose, validator behavior, and tests agree.
- [ ] Deterministic tests pass.
- [ ] Installable package validation passes.
- [ ] Frozen baselines pass offline integrity checks.
- [ ] Full semantic regression was run when required, with the report result recorded for review.
- [ ] No local hook, personal path, credential, or host-specific configuration is included.
